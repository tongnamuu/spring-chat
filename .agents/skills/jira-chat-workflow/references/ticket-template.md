# CHAT Ticket Template

Use this structure for implementation tickets. Omit sections that genuinely do not apply.

```text
배경
- 현재 동작과 문제를 설명한다.
- 관련 모듈, API, 이벤트 또는 사용자 흐름을 명시한다.

목표
- 이 티켓에서 달성할 결과를 한두 문장으로 정의한다.

작업 범위
- 변경할 기능과 시스템 경계를 나열한다.
- 데이터 모델, API, 메시징 또는 UI 계약 변경을 명시한다.

완료 조건
- [ ] 외부에서 관찰 가능한 동작으로 작성한다.
- [ ] 오류, 재시도, 동시성 등 중요한 실패 조건을 포함한다.
- [ ] 테스트로 검증 가능한 문장으로 작성한다.

테스트 계획
- 단위 테스트
- 통합 테스트
- 필요한 수동 검증

제외 범위
- 후속 티켓으로 분리할 내용을 명시한다.
```

## Writing Rules

- 제목은 결과 중심으로 간결하게 작성한다.
- 구현 방법만 쓰지 말고 사용자 또는 시스템 동작을 완료 조건으로 정의한다.
- `적절히`, `정상적으로`, `필요한 경우` 같은 검증 불가능한 표현을 피한다.
- 현재 코드에 없는 기능을 이미 존재한다고 전제하지 않는다.
- 보안, 권한, 중복 처리, 순서 보장, 장애 복구가 관련되면 완료 조건에 포함한다.
